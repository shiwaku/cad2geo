# 設計書: cad2geo — DWG / DXF を地図に載るデータへ変換する

作成: 2026-10-12 / 状態: **設計中**（実装未着手）

## 1. 目的

CAD 図面（DWG / DXF）を GeoJSON / FlatGeobuf に変換し、MapLibre GL JS などの Web 地図に正しい位置で重ねられるようにする。

- DWG と DXF を**同じコード**で読む（Rust の core を CLI とブラウザ版で共有する）
- 単位（mm など）と位置合わせを扱い、**市販 CAD を使わずに**図面から地図に載るデータまでを 1 本で通す
- ブラウザ版は**変換サーバーなし**で動かす（図面を外部に送らなくて済む）

背景は 2 つある。

1. 2024 年 4 月に顧客提供の DWG（平面直角座標系 9 系、mm 単位、AC1032）を GIS データ化したとき、AutoCAD で DXF に変換 → `ogr2ogr` → geopandas で座標を 0.001 倍、と 3 つの道具をまたいだ（esa #1825 / #1837 / #1839）
2. 社内で CAD を Web 地図に載せたい需要が増えている（建設コンサル系の案件、CAD ビューア開発）。ブラウザで DWG を読む手段（acadrust / LibreDWG の WASM 版）もこの夏に揃った

## 2. スコープ

| | Phase 1 で含む | 含まない（Phase 2 以降） |
|---|---|---|
| 入力 | DWG / DXF（R12〜2018 形式）のモデル空間 | ペーパー空間、外部参照（XREF）の解決、SXF（.sfc / .p21）、DGN |
| 図形 | 線・ポリライン・円弧・円・楕円・スプライン・点・文字・ブロック参照・寸法（匿名ブロック経由） | HATCH のポリゴン化、3D ソリッド・メッシュ、プロキシオブジェクト（件数だけ報告） |
| 位置合わせ | 座標付き図面（EPSG 指定）、基準点＋回転角＋縮尺、対応点（2 点以上） | 図面内の GEODATA（AutoCAD の地理位置情報）の読み取り、アフィン以上の変形 |
| 出力 | GeoJSON（WGS84）、FlatGeobuf（任意の CRS） | PMTiles の直接出力（Phase 1 は tippecanoe に任せる） |
| 形態 | CLI、ブラウザ版（WASM + MapLibre） | QGIS プラグイン、サーバー API |

## 3. 入力: DWG と DXF

### 3.1 DWG の仕様は公開されていない

DWG は Autodesk の独自バイナリ形式で、仕様は公開されていない。公式に読み書きできるのは Autodesk 製品と、同社の有償 SDK（RealDWG）のライセンス製品である。OSS が DWG を読めるのは、Open Design Alliance（ODA）が解析結果を「Open Design Specification for .dwg files」として無料公開しているなど、リバースエンジニアリングの蓄積があるためだ。

これが設計に効く点は 3 つある。

- **完全に読める保証はない。** 新しい形式（AC1032）や珍しいエンティティは欠ける可能性がある。DXF は Autodesk が仕様（DXF Reference）を公開しているので、DWG より確実に読める
- **実ファイルでの検証が必須。** 合成データだけで済ませない（§8）
- **逃げ道を用意する。** 直接読めない DWG は、ODA File Converter（無料）で DXF にしてから読む経路を CLI に持たせる（§3.4）

「DWG」の名称は Autodesk との商標問題の経緯があるため、ドキュメントでは「DWG ファイルを読み込める」という説明的な表現にとどめ、公式対応を連想させる書き方はしない。

### 3.2 読み込みライブラリ: acadrust

[acadrust](https://github.com/hakanaktt/acadrust) を使う。

| 項目 | 内容 |
|---|---|
| ライセンス | MPL-2.0（ファイル単位の弱いコピーレフト。MIT のこのリポジトリから依存として使える） |
| 形式 | DWG・DXF（ASCII / バイナリ）の読み書き |
| バージョン | AC1009 (R12) / AC1012 (R13) / AC1014 (R14) / AC1015 (2000) / AC1018 (2004) / AC1021 (2007) / AC1024 (2010) / AC1027 (2013) / AC1032 (2018+) |
| WASM | `wasm32-unknown-unknown` でのビルドを CI で確認している。社内の dwg-maplibre（groovyjovy/dwg-maplibre）で `acadrust = "0.4.1"` を WASM 化して動いた実績がある |
| 文字コード | 2007 より前の図面のコードページ（約 40 種）を自動判定 |
| 未確認 | `$INSUNITS` の取得 API、GEODATA オブジェクトの対応、OCS（押し出し方向）の扱い。**実装の最初に確認する** |

比較した他の選択肢と、採らなかった理由:

| 候補 | 理由 |
|---|---|
| LibreDWG / libredwg-web | GPL。DWG は 2018 形式まで。パース結果が独自 JSON |
| GDAL（DXF ドライバ / libopencad） | DXF は良いが、DWG は libopencad で R2000 まで。GDAL の DWG ドライバ本体は ODA Drawings SDK（有償）が必要。WASM 化も重い |
| ODA Drawings SDK | 有償（ODA 会員）。OSS の個人リポジトリには合わない |
| ezdxf（Python） | DXF のみ。WASM で動かせない。**検証データの生成には使う**（§8） |

### 3.3 バージョンと文字コード

| 形式 | 文字列の格納 | 注意点 |
|---|---|---|
| DXF R2007 以降 | UTF-8 | 素直に読める |
| DXF R2004 以前 | `$DWGCODEPAGE` のコードページ（日本語なら `ANSI_932` = cp932）。`\U+XXXX` のエスケープも混じる | 2024 年の作業で「新しい形式の DXF で日本語が文字化けした」のは書き出し側の問題だった可能性がある。両方向を検証データに入れる |
| DWG 2007 以降 | UTF-16 | 素直に読める |
| DWG 2004 以前 | コードページ | acadrust の自動判定に任せ、`--codepage` で上書きできるようにする |

MTEXT は書式コード（`\P` 改行、`\f...;` フォント、`{\C1;...}` 色など）を含む。属性には書式を除いたプレーンテキストを入れ、元の文字列は `--keep-raw-text` のときだけ残す。`%%c`（φ）、`%%d`（°）、`%%p`（±）は記号に置き換える。

### 3.4 直接読めない DWG の逃げ道

```
cad2geo convert drawing.dwg --via-oda ...
```

ODA File Converter を外部コマンドとして呼び、一時ディレクトリに DXF（AC1024 = 2010 形式）を書き出してから読む。実行ファイルは `--oda-path` または環境変数 `ODA_FILE_CONVERTER` で指定する。ブラウザ版にはこの経路はない（読めなければ「DXF に変換してから入れてほしい」と表示する）。

ODA File Converter を他のツールから自動で呼んでよいかは、ODA の利用条件を実装前に確認する（§10）。

## 4. 座標変換パイプライン

```
CAD 座標 (図面単位)
  │ ① 単位変換        図面単位 → m
  │ ② 位置合わせ      ローカル座標 → 投影座標（平面直角座標系など）
  │ ③ 座標系変換      投影座標 → 出力 CRS（GeoJSON なら WGS84）
  ▼
出力座標
```

### 4.1 ① 単位変換

`$INSUNITS` から図面単位を決める。

| `$INSUNITS` | 単位 | m への倍率 |
|---:|---|---:|
| 0 | 単位なし | 指定必須（`--units`） |
| 1 | インチ | 0.0254 |
| 2 | フィート | 0.3048 |
| 4 | ミリメートル | 0.001 |
| 5 | センチメートル | 0.01 |
| 6 | メートル | 1 |

- `--units` を指定すれば `$INSUNITS` より優先する（ヘッダが嘘をついている図面がある）
- `$INSUNITS` が 0 で `--units` も無ければ**エラーにする**。黙って m とみなすと、mm 図面が 1000 倍の大きさで地球の反対側に出る
- 座標付き図面で座標値の桁から単位を推定するヒューリスティック（例: 9 系の Y が ±数十万なら m、±数億なら mm）は `info` サブコマンドで**提案として表示するだけ**にし、自動適用はしない

### 4.2 ② 位置合わせ

図面には 2 種類ある。

| 種類 | 例 | 座標 | 必要な情報 |
|---|---|---|---|
| 座標付き図面 | 測量図、平面図（公共測量） | 既に平面直角座標系などの値 | CRS（`--crs EPSG:6677`）だけ |
| ローカル図面 | 建築平面図、詳細図 | 原点 (0,0) 基準 | 地図上の位置・向き・縮尺 |

ローカル図面の位置合わせは 2 つの指定方法を用意する。どちらも内部では**相似変換**（平行移動＋回転＋一様な縮尺）に正規化する。

**A. 基準点＋回転角＋縮尺**

```
--anchor-cad 0,0              図面上の基準点（図面単位）
--anchor-map 139.7671,35.6812 地図上の位置（--anchor-crs で CRS を指定。既定は EPSG:4326）
--rotation 23.5               図面の上方向から真北への回転（度、反時計回り正）
--scale 1                     単位変換後の追加倍率（既定 1）
```

**B. 対応点**

```
--gcp gcp.csv   # cad_x,cad_y,map_x,map_y（map 側の CRS は --gcp-crs）
```

- 2 点なら相似変換が一意に決まる
- 3 点以上なら最小二乗で相似変換を推定し、**各点の残差と RMSE を表示する**。残差が大きい点は指定ミスか図面の歪みなので、警告して処理は続ける
- アフィン変換（縦横で縮尺が違う、せん断がある）は Phase 1 では入れない。CAD 図面は本来歪んでいないはずで、自由度を上げると指定ミスを吸収して気づけなくなる

**A / B の地図側座標**は、計算の前に平面直角座標系（または `--work-crs` で指定した投影座標系）に変換してから相似変換を解く。経緯度のまま回転・縮尺を掛けると、東西と南北で縮尺が違うため形が歪む。`--work-crs` を省略したときは、地図側の点の経度から平面直角座標系の系を選ぶのではなく、**指定を必須にする**（系の境界付近で誤った系を選ぶと気づきにくいため）。

**X / Y の入れ替え。** 測量では X が北、Y が東だが、CAD の X は右（東）である。2024 年の DWG は CAD の X = 東で、そのまま EPSG:6677 として地図と重なった。ただし測量の X / Y をそのまま CAD の X / Y に入れた図面もありうるため、`--swap-xy` を用意する。`info` で外接矩形を平面直角座標系の範囲と照らし、入れ替えたほうが妥当なら提案する。

### 4.3 ③ 座標系変換

座標系変換は純 Rust の [proj4rs](https://github.com/3liz/proj4rs) を使う。PROJ（C ライブラリ）は WASM 化が重く、ブラウザ版と共有できないため。

- 平面直角座標系（JGD2011, EPSG:6669〜6687）と JGD2000（EPSG:2443〜2461）の proj 文字列は core に**表として持つ**。EPSG データベースは同梱しない
- それ以外の CRS は `--crs "+proj=..."` で proj 文字列を直接受け付ける
- JGD2011 → WGS84 は同一とみなす（差は Web 地図の表示では問題にならない）。JGD2000 も同様だが、2011 年以降の地殻変動ぶん（東北で最大数 m）はずれる。これは変換せず、README に注意として書く

## 5. エンティティの変換

### 5.1 対応表

| CAD エンティティ | 出力ジオメトリ | 補足 |
|---|---|---|
| LINE | LineString | |
| LWPOLYLINE / POLYLINE (2D) | LineString（閉じていれば `--close-polygons` で Polygon） | ふくらみ（bulge = tan(θ/4)）を円弧として折れ線化 |
| ARC / CIRCLE / ELLIPSE | LineString | 折れ線化（§5.3） |
| SPLINE | LineString | 制御点ではなく評価した曲線を折れ線化 |
| POINT | Point | |
| TEXT / MTEXT | Point（挿入点） | 文字列・高さ・回転角を属性に入れる（§6） |
| INSERT | 中身を展開 | 入れ子・負の縮尺（鏡像）・MINSERT（配列）を含む。ATTRIB は文字として出す |
| DIMENSION | 匿名ブロック（`*D...`）を展開 | 寸法値の文字も TEXT として出る |
| SOLID / 3DFACE | Polygon | Z は捨てる |
| HATCH | Phase 1 は境界線を LineString で出すだけ | ポリゴン化は Phase 2 |
| 3DSOLID / REGION / BODY / MESH | 出さない | 件数を報告 |
| プロキシ・未対応 | 出さない | エンティティ名ごとの件数を報告（黙って消さない） |

### 5.2 落とし穴

- **OCS（押し出し方向）。** 円弧・円・LWPOLYLINE などは、押し出し方向 (210 グループ) で決まる座標系（OCS）で座標を持つ。鏡像コピーした円弧は押し出し方向が (0, 0, −1) になり、そのまま描くと**左右反転した位置に出る**。任意軸アルゴリズムで WCS に戻してから折れ線化する
- **ブロックの入れ子と変換の合成。** INSERT の挿入点・縮尺・回転・押し出し方向を、親から子へ順に掛ける。ブロック基点（BLOCK の基点）を引くのを忘れない
- **レイヤ 0 と BYBLOCK。** ブロック内のレイヤ 0 の図形は、挿入先の INSERT のレイヤに属する。色・線種の BYBLOCK も挿入先から継承する
- **非表示レイヤ。** 凍結・非表示のレイヤは既定で出さない（`--include-hidden-layers` で出す）
- **ペーパー空間。** 既定ではモデル空間だけを出す。図枠や表題欄がペーパー空間にある図面は多い

### 5.3 曲線の折れ線化

弦の誤差（曲線と折れ線の最大の離れ）を**地上の長さ**で指定する。既定 `--chord-tolerance 0.01`（m）。図面単位で指定すると、mm 図面と m 図面で同じ値が 1000 倍違う意味になってしまうため、単位変換後の長さで決める。分割数には上限（1 円あたり 720）と下限（8）を置く。

## 6. 出力

### 6.1 形式

| 形式 | CRS | 用途 |
|---|---|---|
| GeoJSON | WGS84 のみ（RFC 7946） | Web 地図・ブラウザ版の書き出し・tippecanoe の入力 |
| FlatGeobuf | 任意（`--target-crs`、既定は作業 CRS） | QGIS での確認、平面直角座標系のまま渡したいとき |

GeoJSON で投影座標を出したい要望には応えない（RFC 7946 に反し、読み手のソフトによって解釈が割れる）。その用途は FlatGeobuf で出す。PMTiles は tippecanoe で作る手順を README に書く。

### 6.2 属性

| 属性 | 型 | 内容 |
|---|---|---|
| `layer` | string | レイヤ名 |
| `entity` | string | 元のエンティティ種別（`LINE`、`ARC` など） |
| `handle` | string | エンティティハンドル（図面内で一意。ブロック展開時は INSERT のハンドルを `/` でつなぐ） |
| `block` | string \| null | 展開元のブロック名（入れ子なら `/` でつなぐ） |
| `color` | string | 解決後の色（`#rrggbb`）。BYLAYER / BYBLOCK / ACI / トゥルーカラーをすべて解決する |
| `linetype` | string | 解決後の線種名 |
| `lineweight` | number \| null | 線の太さ（mm） |
| `text` | string \| null | 文字（TEXT / MTEXT / ATTRIB のみ） |
| `text_height` | number \| null | 文字高（**地上の m**） |
| `text_rotation` | number \| null | 文字の回転角（**真北基準**。位置合わせの回転を加味した値） |

`color` をそのまま MapLibre の `["get", "color"]` で使えば、図面の色で描ける。ブラウザ版はこれを使い、CLI は同じスタイルの JSON を `--emit-style` で書き出せるようにする（Phase 1 の最後に余力があれば）。

## 7. 形態

### 7.1 CLI

```
cad2geo info <file>
    形式・バージョン・単位（$INSUNITS）・コードページ・外接矩形・レイヤ一覧・
    エンティティ種別ごとの件数・未対応エンティティの件数・座標付き図面かどうかの推定

cad2geo convert <file> -o <out.geojson|out.fgb>
    [--crs <EPSG|proj>]                      座標付き図面の CRS
    [--units mm|cm|m|in|ft]                  $INSUNITS の上書き
    [--anchor-cad x,y --anchor-map x,y [--anchor-crs] --rotation deg [--scale s]]
    [--gcp <csv> [--gcp-crs]]
    [--work-crs <EPSG|proj>]                 位置合わせを解く投影座標系
    [--target-crs <EPSG|proj>]               FlatGeobuf の出力 CRS
    [--swap-xy] [--layers a,b] [--exclude-layers c]
    [--include-hidden-layers] [--close-polygons]
    [--chord-tolerance m] [--codepage cp932]
    [--via-oda [--oda-path]]
```

未対応エンティティや位置合わせの残差は標準エラーに要約し、`--report <json>` で機械可読でも出す。

### 7.2 ブラウザ版

- Vite + MapLibre GL JS。WASM（wasm-bindgen）は **Web Worker** で動かし、大きな図面でも UI を固めない
- 背景地図は地理院タイル（淡色地図、写真）
- 操作の流れ:
  1. ファイルをドロップ → `info` 相当の結果（バージョン・単位・レイヤ）を表示
  2. 「座標付き」なら CRS を選ぶ（平面直角座標系の系をプルダウンで）。「ローカル」なら地図の中央に仮置き
  3. ローカル図面は、図面上と地図上を交互にクリックして対応点を 2 点以上置く。または移動・回転のハンドルで合わせる。残差を表示する
  4. レイヤごとの表示切替
  5. GeoJSON と、位置合わせのパラメータ（JSON。CLI の `--gcp` と同じ内容）を書き出す
- **図面はブラウザの外に出さない。** 通信するのは背景地図のタイルだけ

位置合わせのパラメータを CLI と共有できるようにしておくと、ブラウザで目で合わせて、大量の図面は CLI で一括変換する、という使い方ができる。

## 8. 検証データとテスト

第三者の図面はリポジトリに入れない（`testdata/` は `.gitignore` 済み。取得手順だけ `testdata/README.md` に書く）。2024 年に使った顧客提供の DWG は貸与品なので使わない。

### 8.1 合成した建築平面図（自作）

`tools/gen_testdata/`（Python + ezdxf）で生成する。

- **形**: 実在する建物の外形（PLATEAU 建築物、または基盤地図情報の建築物外周線から矩形に近いものを 1 棟選ぶ。候補は実装時に決める）に合わせて、外壁・内壁・柱・通り芯を描く
- **単位**: mm（`$INSUNITS = 4`）。原点は建物の角、図面の上方向は真北から**意図的に回転**させる（例: 23.5°）
- **日本語**: レイヤ名（`壁`、`建具`、`室名`、`寸法`、`通り芯`）、室名の TEXT / MTEXT（`事務室`、`会議室`、`給湯室`）、`%%c` などの特殊記号
- **落とし穴を仕込む**: 建具を入れ子ブロックにする、鏡像コピーした扉（押し出し方向 −Z の円弧）、負の縮尺の INSERT、属性付きブロック（部屋番号）、寸法線、ペーパー空間の図枠、非表示レイヤ、`$INSUNITS = 0` の版
- **形式のバリエーション**:
  - DXF: R2010（UTF-8）と R2000（cp932、`$DWGCODEPAGE = ANSI_932`）
  - DWG: ODA File Converter で AC1032（2018）と AC1015（2000）に変換
- **正解**: 基準点・回転角と、主要な頂点の正解座標（平面直角座標系と経緯度）を `expected.json` に出す

座標付き図面の検証用に、同じ平面図を 9 系の座標に置いた版（2024 年の DWG と同じ条件: 座標付き・mm・AC1032）も作る。

### 8.2 公開されている DWG

### 8.3 テスト

| 種類 | 内容 | 合格条件 |
|---|---|---|
| 単体 | 単位換算、相似変換（2 点 / 最小二乗）、OCS、bulge、折れ線化の誤差、MTEXT の書式除去 | 手計算の値と一致 |
| 正解比較 | 合成データの全バリエーションを変換し `expected.json` と比べる | 頂点の誤差が投影座標で 1 mm 以内、経緯度で 1 cm 相当以内。日本語文字列が完全一致。エンティティ件数が一致 |
| DWG / DXF の一致 | 同じ図面の DXF 版と DWG 版の出力を比べる | ジオメトリと属性が一致（DWG の読み込み不具合の検出） |
| GDAL との比較 | DXF を `ogr2ogr` でも変換し、ジオメトリを比べる | 差分を記録する（GDAL を正解とはみなさない。違いの理由を説明できればよい） |
| 実ファイル | §8.2 を `info` / `convert` に通す | 落ちない。未対応エンティティが報告される |

## 9. 構成

```
cad2geo/
├─ Cargo.toml              workspace
├─ crates/
│  ├─ core/                読み込み・エンティティ変換・単位・位置合わせ・座標系変換（I/O なし）
│  ├─ cli/                 clap。ファイル I/O、GeoJSON / FlatGeobuf 書き出し、ODA 呼び出し
│  └─ wasm/                wasm-bindgen。core をブラウザ向けに公開
├─ web/                    Vite + MapLibre（pnpm）
├─ tools/gen_testdata/     合成データ生成（Python + ezdxf、uv）
├─ testdata/               取得・生成したデータ（README.md 以外は追跡しない）
└─ docs/
```

- Rust は edition 2024。acadrust は 0.4 系に固定し、更新は検証データを通してから
- core は**ファイル I/O を持たない**（バイト列を受け取り、フィーチャの列を返す）。CLI と WASM で同じコードを使うため
- 開発環境は Windows 11。Rust（rustup）は未導入なので最初に入れる。pnpm のスクリプト実行は `pnpm exec` で直接呼ぶ（script-shell の設定で `pnpm run` が止まる環境のため）

## 10. リスク・未確定事項

| 項目 | 影響 | 対応 |
|---|---|---|
| acadrust がまだ若い（0.4 系） | 読めない図面・API の破壊的変更 | バージョン固定。読めない DWG は `--via-oda` で DXF 経由に逃がす。不具合は最小再現データを作って上流に報告する |
| DWG の仕様が非公開 | 新しい形式・珍しいエンティティが欠ける | 実ファイルで検証。DXF 版との一致テストで検出する |
| `$INSUNITS` / GEODATA / OCS の acadrust での扱いが未確認 | 単位・位置・鏡像がずれる | 実装の最初の調査項目にする。足りなければ DXF のグループコードを直接読む |
| proj4rs の精度と対応範囲 | 座標系変換のずれ | 平面直角座標系の数点を PROJ（pyproj）の結果と比べるテストを入れる |
| 大きな図面をブラウザで読むとメモリが足りない | ブラウザ版が落ちる | Worker で処理し、上限（例: 100 MB）を超えたら CLI を案内する |
| ODA File Converter を自動で呼ぶことの可否 | `--via-oda` の配布可否 | ODA の利用条件を確認するまで、`--via-oda` は「利用者が自分で入れたものを呼ぶ」だけにする |
| ETSU の DWG のライセンス | 検証データに使えない | 取得時にファイル単位の表記を確認。リポジトリには入れない |
| 「DWG」の名称 | 商標の扱い | 説明的な表現にとどめる（§3.1） |
